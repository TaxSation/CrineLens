CrimeLens mini dataset (synthetic)
==================================

All records are synthetic. Names, numbers, accounts, cases and events do not
describe real people or real activity. Generated by generate_mini_dataset.py
(seed 189, deterministic). All files are UTF-8 CSV.

PURPOSE
-------
A very small dataset for building and demonstrating the CrimeLens prototype
screens end to end. It keeps the column names of the larger 250-person PS 189
dataset, and adds hand-planted patterns with an answer key.

It is for showing how the output looks. Patterns were placed by hand, so
detecting them shows the pipeline works. It is not evidence of real-world
accuracy, and no precision, recall or F1 from this data should be presented
as a performance claim.

TIMELINE
--------
Activity: 2026-06-01 to 2026-08-31. Main incident: CASE0001 on 2026-08-20
(Ahmedabad_Zone_5). "48 hours before the incident" = 2026-08-18 to 2026-08-19.

CHANGES FROM THE LARGER 250-PERSON DATASET
------------------------------------------
Removed   persons.risk_label (inconsistent with the data in the original, and it
          leaks an answer).
Added     cdr.caller_phone_id and receiver_phone_id (phone-level calls, so the
          shared number of the alias can be found); fir_reports.language;
          organization_members.csv; relationship types OWNS_PHONE, WORKED_FOR
          and TRANSFERRED_TO.
Renamed   event_type loitering_simulation -> loitering; outcomes lose the
          "_simulation" suffix.
Fixed     SMS have zero duration; FIRs and intel reports are dated on or after
          the incident; criminal-history year equals the case year; each camera
          sits at one location; vehicle-only sightings have no person; frozen
          accounts have no transactions; call times follow a daytime rhythm.
Names     FIR, intel and social text use names, registration numbers and phone
          numbers, so extraction has real work to do. Alias and format
          variants exist (see PAT04).

KNOWN LIMITS
------------
- Twenty people is enough to show the screens, not to stress performance.
- Hidden link: by common neighbours alone P0007-P0012 ranks 16th among
  cross-community non-edges. It only stands out when co-location and the
  two-step money path are combined with the common neighbours (P0005, P0019).
- The random baseline also produces other high common-neighbour pairs (for
  example P0005 - P0001). Expect some false candidates.
- The graph is small: the highest call degree is 10.

NOTES
-----
- relationships.csv is a convenience view for the frontend. Calls, transfers
  and phone ownership are modelled as edges here, but the plan's decision on
  how to model them (design document D10) is still open. Treat the raw tables
  as the source of truth. evidence_class, confidence and reliability are not
  included because their scales are undecided (D11).
- Suggested demo path: Command Center leads -> graph with communities (bridge
  P0005) -> timeline, 48h before 2026-08-20 (spike, new edges) -> evidence
  drawer on a transfer in the chain -> copilot "why is P0004 a priority?" ->
  contradiction on P0006 -> report.
